# حضور

تطبيق Android عربي لتسجيل حضور الطلبة بواسطة بطاقات QR، مصمم للعمل يوميًا دون خادم أو حساب أو اتصال بالإنترنت. قاعدة Room الموجودة على الجهاز هي مصدر الحقيقة، ويمكن نقل التقارير والنسخ الاحتياطية إلى Windows عبر USB أو مدير الملفات.

## المزايا

- مسح QR متتابع عبر CameraX وML Kit المضمّن، مع إعادة تسليح تلقائية وصوت واهتزاز.
- منع التكرار ذريًا بقيد فريد على الطالب/اليوم/السنة، مع حالة واضحة للمسح المكرر.
- تحديد حاضر/متأخر وفق وقت قابل للتعديل.
- تعديل وحذف السنوات والصفوف والقاعات والتقويم، وتعديل الطلبة وأرشفتهم أو حذفهم نهائيًا بعد التأكيد.
- استيراد قالب XLSX والتحقق منه قبل معاملة الاستيراد، وتصدير XLSX حقيقي.
- إنشاء ملف PDF لبطاقات QR لكل الطلبة النشطين أو لطلبة تحددهم من القائمة؛ الرمز يحمل معرفًا عشوائيًا فقط.
- حضور يدوي وتعديل الحالات وحذف السجلات للمدير، مع سجل تدقيق.
- لوحة يومية وتقارير يومية/أسبوعية/شهرية/مخصصة مع فلتر الصف والقاعة، وتصدير PDF/XLSX وطباعة.
- نسخ احتياطي محلي مشفّر بكلمة مرور مع metadata والتحقق ونسخة أمان قبل الاستعادة.
- PIN إدارة محلي مشفّر اشتقاقيًا، ودور مشغّل محدود.
- RTL وMaterial 3 وتخطيط Navigation Rail للأجهزة اللوحية.

لا يحتوي `AndroidManifest.xml` على إذن الإنترنت.

## المتطلبات والبناء

- Android Studio حديث أو JDK 17/21.
- Android SDK 35 وBuild Tools 35.

على Windows:

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug
```

لأن اسم مجلد المشروع عربي، توجّه مخرجات Gradle المؤقتة إلى `%TEMP%\omega-attendance-build-v2\app`. ملف APK الناتج يوجد في:

```text
%TEMP%\omega-attendance-build-v2\app\outputs\apk\debug\app-debug.apk
```

نسخة الإصدار الموقّعة تحمل اسم `Hodoor-<version>-Release.apk`. لا تحمل إذن الإنترنت أو قراءة حالة الشبكة. لمفتاح التوقيع وتعليمات حفظه وبناء التحديثات، راجع وثيقة Signing. لا يمكن تحديث نسخة debug بها مباشرة؛ إزالة النسخة التجريبية تمسح بياناتها المحلية.

اختبارات Room على جهاز/محاكي:

```powershell
adb -s emulator-5554 shell am instrument -w com.omega.attendance.test/androidx.test.runner.AndroidJUnitRunner
```

## بدء الاستخدام

1. في أول تشغيل عيّن PIN للإدارة.
2. من الإعدادات أدخل اسم المدرسة وتحقق من السنة النشطة. تُنشأ الصفوف الستة والقاعات 1–12 تلقائيًا ويمكن تعديلها أو حذفها.
3. أضف طلبة أو نزّل قالب Excel واستورد القائمة.
   من شاشة الطلبة اختر «بطاقات QR للكل» لطباعة جميع البطاقات، أو «تحديد طلبة» لإنشاء بطاقات لمجموعة محددة.
4. افتح شاشة المسح وامنح إذن الكاميرا.
5. في نهاية اليوم افتح التقارير، اختر الصف والقاعة إذا لزم، ثم احفظ PDF أو XLSX في موقع تختاره.

الحذف النهائي للطالب يزيل سجلات حضوره أيضًا بعد تأكيد صريح. الأرشفة توقف QR وتُبقي السجلات، ويمكن إعادة تفعيل الطالب من قائمة «المزيد». حذف السنة غير النشطة يزيل صفوفها وتقويمها فقط إذا لم يكن لديها طلبة أو سجلات حضور. حذف القاعة يترك قاعة الطلبة المرتبطين بها غير محددة. احفظ نسخة احتياطية قبل حذف بيانات حقيقية.

تنبيه خصوصية: النسخ الجديدة بامتداد .omega مشفّرة بكلمة مرور تختارها. احتفظ بكلمة المرور والملف في مكانين آمنين؛ ضياع كلمة المرور يمنع الاستعادة. يمكن قراءة نسخ ZIP القديمة غير المشفّرة لاستعادة بياناتها ثم إنشاء نسخة مشفّرة جديدة.

في نسخة debug فقط يظهر زر إنشاء 1,000 طالب وهمي و100,000 سجل لاختبار الحمل. لا تستخدم بيانات حقيقية للتطوير.

## استكشاف الأخطاء

- رفض الكاميرا: فعّل الإذن من إعدادات Android ثم عد إلى شاشة المسح.
- خطأ استيراد: استخدم القالب وتأكد أن أسماء المرحلة/الصف/الشعبة/القاعة مطابقة لما في التطبيق.
- فشل الحفظ: اختر موقعًا قابلًا للكتابة وتأكد من وجود مساحة وعدم نزع USB أثناء العملية.
- تعذر الاستعادة: التطبيق يرفض ZIP الناقص أو قاعدة بيانات لا تحمل توقيع SQLite الصحيح.
